# GW（hgw）を FP32 オプションで速くする計画（2026-09-27 改訂）

目的: `--mp --fp32` の GW を RTX 5090 ×2 ＋ CPU 64 コアで速く回す。精度は FP32 の積と同等以上。
他の GPU や複数の計算が同時に走る場合にも、無理なく動くようにする。

## 方針（決まったこと）

- **ユーザーが選ぶのは精度だけ**（tf32 / fp32 / fp64）。行列積や逆行列の中身（cuBLAS、実数 SGEMM への組み替え、Ozaki など）は、
  インストール時に測った結果から演算ごとに自動で選ぶ。選んだものは stdout に出す。手で上書きもできる
- **並列は MPI だけ**。OpenMP は使わない。GPU 1 枚に中心のランク 1 つ
- CPU の仕事（四面体の重み tetwt5）は、hgw の外の CPU の段（ファイル渡し）と、hgw と並ぶ補助ランク（MPMD）の 2 通りを用意する
- 同時に走る計算の分け合いは起動時の割り当てで済ませる（GPU は今の `gpu.lock`、CPU は `-np`）。実行中に調整する仕組みは作らない
- **段ごとに確認してから次へ進む**。各段で 6³ ベンチの Σc が基準と合うこと、テストに通ることを確かめ、研究ログに記録してコミットする

## いまの数字（LiTi2O4 6³ の `hgw` 1 回、kt1）

| 構成 | 秒 |
| --- | --- |
| 基準（`c1b4b097a`） | 833 |
| Hilbert 変換を GPU へ（E1） | 722 |
| ＋ GEMMul8 単精度 7 分解（E2） | 629 |
| ＋ 実数 SGEMM への組み替え（E4、GEMMul8 なし） | 570 |

残る大物は Σc の行列積、matinv（FP64 の LU、1 q 10 秒）、tetwt5（CPU、9³ で 1 q 21 秒）。

## 段階

各段で共通の確認:
(a) 6³ ベンチ（kt1 `bench_hgw666`）で SECU が基準と合うこと。FP32 系は 1e-5 eV 以内、ビット一致を狙う段はビット一致。
(b) TestInstall の GPU テスト（`--gpu`、`--gpu --mp`）と `Samples/MLOQSGW` に通ること。
(c) `hgw` の時間を測ること。
開発は kt1 の `~/ecalj_dev`（`~/bin_dev`）で行い、本番の `~/ecalj` は走行中に触らない。

### 段 0 いまの計測をそろえる（実行中）
- E4 をやり直して Σc の差を取る。E3（倍精度 ＋ Ozaki の `hgw`）で倍精度の基準と費用を取る。空いた GPU でマイクロベンチを取る
- Ozaki の「固定の行列の使い回し」（GEMMul8 の `skip_scalA/B`）のマイクロベンチ: 下の表の形で、使い回しあり・なしの Ozaki、組み替え、cuBLAS を比べる
- 完了の条件: 数字が研究ログにそろう

### hgw で片方の行列が固定される積（Ozaki の使い回しが効く場所）

| 場所 | 固定される行列 | 替わる行列 | 固定の範囲 |
| --- | --- | --- | --- |
| Σc 実軸 | $W(\omega)$（1053²、周波数ごと） | その周波数の zmel の列（n ≈ 数百） | 1 q の全 KXloop（約 840 回） |
| Σc 虚軸 | $W(i\omega)$（11 周波数） | zmel（n ≈ 5 万） | 1 q の全 KXloop |
| Σc 虚軸（重みを積の後に掛ける形に直すと） | zmel | $W(i\omega)$ | 11 周波数 |
| zmel の M2E 変換 | m2e の基底 | zmelt | 1 q の全 KXloop |

- 実軸は n が小さく分解の費用が効くので、今は Ozaki が cuBLAS より遅い（22.6 対 31.4 TFLOPS）。使い回しで逆転しうる
- 分解した形を置く場所: 虚軸の 11 周波数や m2e の基底なら数百 MB。実軸の約 330 周波数ぶんは数 GB〜10 GB なので測ってから決める。
  キャッシュは q ごとに捨てる

### 段 1 cgemm ラッパーと方法の切り替え
- 実数 SGEMM への組み替えを広げる: 任意の opA、opB=N、複素 alpha/beta（beta は先に C に掛ける）。hgw の主な積はこれで全部入る
- `m_blas` の gemm に「この行列は前と同じ」を伝える引数（キー。周波数番号など）を足す。Ozaki のときはそのキーで分解した形を
  使い回し、組み替えや cuBLAS のときは無視する。この段では引数を通すだけにする
- `m_blas` に「演算の種類 × 大きさの区分 → 方法」の表を持たせる。この段では既定値を固定の規則で持つ
  （fp32: 大きな積は組み替え、小さな積は cuBLAS／fp64: Ozaki／tf32: cuBLAS TF32）。起動時に表を stdout に出す
- 完了の条件: 共通の (a)(b)(c)、E4 以上の速さ

### 段 2 インストール時の計測と方針ファイル
- 候補は演算ごとに 2〜3 つ（fp32: cuBLAS、組み替え、Ozaki（使い回しあり）／fp64: cuBLAS と Ozaki／逆行列: 後述）。
  上の表の場所ごとに、hgw の実際の形で速さと誤差を測る
- 結果を `<bindir>/ecalj_gemm_policy.toml`（GPU 名、CUDA の版、演算ごとの方法、数行）に書く。InstallAll（GPU 版）の最後に回す
- `m_blas` は起動時に読むだけ。ファイルが無いときや GPU 名が違うときは段 1 の規則に戻る。毎回同じ方法になるので結果も再現する
- 完了の条件: kt1 で段 1 と同じ選択・同じ結果になる

### 段 3 matinv の混合精度
- `zminv_mixed_d`（`458bd1868`、今は `ECALJ_MATINV_MIXED=1` で有効）を hgw で確かめる。FP32 の LU ＋ Newton（fp32 は 1 回、fp64 は 2 回）
- 合えば精度ごとの既定にする（方針の表に入れる）
- 完了の条件: 共通の (a)(b)(c)、matinv が 1 q 10 秒 → 2〜3 秒

### 段 4 tetwt5 を hgw の外へ（ファイル渡し）
- 四面体の重みの結果（whw と索引の配列）を詰めて書く・読む部品を作る（段 5 の送受信でもそのまま使う）
- gwsc の hgw の直前に CPU の MPI の段を足す。全部の (q, spin) を q で分けて計算し、ファイルに書く
- hgw はファイルがあれば読み、無ければ今どおり自分で計算する。ファイルには固有値の要約を入れ、合わなければ使わない
- 完了の条件: whw と SECU がビット一致。9³ で 1 反復あたり約 350 秒縮む見込み

### 段 5 tetwt5 を補助ランクで（MPMD）
- `mpirun -np N hgw : -np N htetwt` で並べて起動する。`MPI__Initialize` で MPI_APPNUM ごとにコミュニケータを分けるので、hgw の中身は変わらない
- hgw のランクは担当する (q, spin) の並びを相方に 1 回送る。相方はその順に計算して、段 4 の部品で詰めて MPI_Send する（自然に 1 個先読みになる）
- hgw は受け取るだけ。補助がいなければ段 4 の経路か、今の自前の計算に戻る
- 完了の条件: 段 4 とビット一致。各ランクの最初の q 以外で tetwt5 の時間が消える。単一ノードで段 4 とどちらが速いかを測り、既定を決める
  （複数ノードで速い共有ディスクが無い場合は段 5）

### 段 6 倍精度モード（Ozaki）
- 段 0 の E3 をもとに、fp64 の方針（Ozaki の分解数、逆行列は Newton 2 回）を決め、TestInstall の倍精度の GPU テストに通す
- 完了の条件: 倍精度の結果（1e-14 級）と費用（fp32 の何倍か）が研究ログにそろう

### 段 7 本番
- 段 1〜5 が済んだ版で、9³ の `gwsc 10` を回す（必要なら 6³ も取り直す）

### あとで（必要になったら）
- LPT の重みを実測の時間に（2 枚の GPU の終わりのずれ、約 3%）
- 1 つの q を複数の GPU で分ける場合の計測（GPU が q 点より多いとき）
- 同時に走る計算のための、gwsc での CPU コアの確保（`gpu.lock` と同じ要領）
