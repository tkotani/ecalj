# ecalj_auto: Automatic QSGW Calculation System for Materials Project Structures

This package automates QSGW calculations (using the ecalj package) for crystal structures obtained from the Materials Project (MP).  
It is designed for systematic, high-throughput calculations on many materials, efficiently utilizing multi-core machines with a qsub job system.

## Installation

1. **Install ecalj** (see ecalj documentation).
2. No build process is needed for ecalj_auto (Python-based).
3. Edit `config.ini` to set:
    - `api_key` : Your Materials Project API key
    - `epath`   : Path to ecalj binaries
    - `nqsub`   : Number of qsub jobs to run in parallel
    - `ncore`   : Number of cores per qsub job
    - `niter`   : Number of QSGW iterations (not until convergence)
    - `bnd4all` : If True, calculate band dispersions at every QSGW iteration
    - `gw80`    : If True, run QSGW80 ($V_{xc} = 0.8V_{xc}^{QSGW} + 0.2V_{xc}^{LDA}$)

**Note:**  
The total number of MPI cores used is `nqsub × ncore`.  
Edit `jobtemplate` for your cluster (typically only the `-q` section needs changing).

## Usage

### 1. Get POSCAR Files from Materials Project

Run:
```bash
./query.sh
```
- See `query.sh` for options (e.g. `--nsite`, `--include`, `--mag`, `--theoretical`, `--metal`).
- This script creates POSCAR files and a `joblist` in the `INPUT/` directory.

### 2. Run QSGW Jobs

Example (see `jobtestSGA.sh`):
```bash
./auto/jobsubmit.py --inpath INPUT/testSGA --epath /path/to/ecalj/bin/ --nqsub 2 --niter 2 --ncore 32 --bnd4all True
```
- `--inpath` : Directory with input data (from query.sh)
- `--epath`, `--nqsub`, `--niter`, `--ncore`, `--bnd4all` : See above

#### GPU / Mixed Precision Options

To use GPU-accelerated or mixed-precision GW executables, add `--gpu` and/or `--mp`:
```bash
# GPU only
./auto/jobsubmit.py --inpath INPUT/testSGA --epath ~/bin/ --nqsub 2 --ncore 64 --niter 2 --bnd4all True --gpu

# Mixed Precision only
./auto/jobsubmit.py --inpath INPUT/testSGA --epath ~/bin/ --nqsub 2 --ncore 64 --niter 2 --bnd4all True --mp

# GPU + Mixed Precision
./auto/jobsubmit.py --inpath INPUT/testSGA --epath ~/bin/ --nqsub 2 --ncore 64 --niter 2 --bnd4all True --gpu --mp
```
These flags are passed through to `gwsc`, which selects the appropriate binary variants
(e.g., `hrcxq_gpu`, `hrcxq_mp_gpu`, `hsfp0_sc_mp_gpu`, etc.).
The corresponding binaries must be built and installed in the `--epath` directory.

**Notes:**
- `jobsubmit.py` reads `joblist` in the input directory.
- Results are written to `OUTPUT/<name>` (mirroring the input directory structure).
- Job output: `OUTPUT/<name>/jobX.out` (for each qsub job).
- QSGW iteration output: `mp-*/osgw.out`
- Each `mp*/RUN.<name>` contains:
    - `bandplot.*.glt` : Band plot (gnuplot)
    - `tdos.*.glt`     : Total DOS (gnuplot)
    - `pdos*.site*.glt`: PDOS for each site (see `SiteInfo.chk`)

## Test: Compare with Previous Results

To compare eigenvalues between two result directories:
```bash
./testchk.py <dir1> <dir2>
```
- Compares results in `<dir1>` and `<dir2>` for each material.

To extract only important files from your results:
```bash
./packoutput.py OUTPUT
```
- Creates a minimal copy in `OUTPUT_pack/OUTPUT`.

## Changelog

### 2026-04-04: GW1500 mass production fixes (commit 6ade0a8c)

Bug fixes found during GW1500 (1546 materials, QSGW80) mass production on kt1:

1. **gwsc (SRC/exec/gwsc line 152)**: QSGW中のlmfにbmix_reduction=Trueを追加。
   以前はLDA部分のみbmix自動低減が有効で、QSGW iterationではb=0.2固定のため
   アルカリ土類カーバイド/ペルオキシド等で収束せず失敗していた。

2. **run_cmd.py (SRC/exec/run_cmd.py line 1)**: `from utils import remove_files`を追加。
   bmixリトライ時に`remove_files("__mixm")`を呼んでいたが、importが欠けていたため
   NameErrorで落ちていた。

3. **ctrlgenM1.py (SRC/exec/ctrlgenM1.py line 643付近)**: R上限のバグ修正と追加。
   - Na/MgとK/Caの制限が1行に結合されてK/Ca側が無効だった → 分離して修正
   - Rb/Sr (z=37,38): R上限 2.8 追加
   - Cs/Ba (z=55,56): R上限 2.8 追加
   - R=3.0(lmchkデフォルト上限)はアルカリ・アルカリ土類では大きすぎてQSGWで収束しにくい
