# gw_lmfh: one-shot GW and QP energies at arbitrary k (QforGW)

*(draft for ecaljdoc; target location: manual/gw section)*

## Purpose

`gw_lmfh` performs a one-shot GW calculation (G0W0-style) on top of the
current `rst.<sname>` (LDA, or a QSGW restart with `sigm`) and writes
quasiparticle energies to `QPU`. Unlike `gwsc`, which evaluates Σ on the
regular GW mesh only, `gw_lmfh` can evaluate the **diagonal** Σ_nn(ε_n) at
**arbitrary k-points** supplied by the user — e.g. along a band line —
with no interpolation.

## Usage

```bash
gw_lmfh <sname> -np N                            # CPU
gw_lmfh <sname> -np N -np2 M --gpu               # FP64 GPU for hvccfp0/hx0fp0
gw_lmfh <sname> -np N -np2 M --gpu --mp --fp32   # fast path (see below)
```

Requires `ctrlg.<sname>.toml` + `PB.<sname>.toml` in the working directory
(same TOML gate as `gwsc`).

| option | meaning |
|---|---|
| `-np N` | MPI ranks for CPU steps (lmf, hsfp0 exchange) |
| `-np2 M` | ranks for GPU steps; typically 1 per GPU |
| `--gpu` | hvccfp0/hx0fp0 run as `_gpu` variants; the correlation step runs on `hsfp0_gpu` |
| `--mp` | hvccfp0/hx0fp0 run as `_mp_gpu` variants; W files are single precision and are promoted on read by hsfp0 |
| `--fp32` | with `--mp`: true-FP32 GEMMs instead of TF32. **Always use with `--mp`** — TF32 corrupts ill-conditioned dielectric matrices |

## QP energies along a k-line: `QforGW`

Add to `ctrlg.<sname>.toml`:

```toml
[gw]
EMINforGW = -6.0    # eV relative to EF: lowest Sigma target band
EMAXforGW =  6.0    # eV relative to EF: highest Sigma target band

[blocks]
QforGW = """
 0.000  0.000  0.000
 0.375 -0.375  0.000
 0.750 -0.750  0.000
"""
```

- One k-point per line, 3 reals, Cartesian in units of 2π/alat (the same
  convention as `syml` and the q-columns of `QPU`).
- `EMINforGW` / `EMAXforGW` (eV, relative to E_F) restrict the bands for
  which Σ is evaluated.

**`EMAXforGW` is required for off-mesh k-points.** The eigen-decomposition
at such k stores fewer than `nband` states; the remainder are padded with
1d20, and including them as Σ targets aborts with
`sxcf 222: |w-e| out of range`.

After the run, `QPU` contains one block per k-point. The Z=1 quasiparticle
energy is `eQP = eLDA + dSEnoZ`, with `dSEnoZ = SEx + SExcore + SEc − vxc`.

### Caveats

- **Changing the window mid-run:** the exchange files (`SEXU`, `XCU`) and the
  correlation file (`SECU`) must contain the same number of target states.
  If you edit `EMINforGW`/`EMAXforGW` after the exchange stage, rerun
  `hsfp0 --job=3` and `hsfp0 --job=11` before `hqpe`.
- **Memory (CPU correlation):** in QPE mode each rank holds the full
  W(ω) stack (≈ ngb²·nω·16 B; several GB/rank for medium systems). Reduce
  `-np` if you hit the node memory; the GPU binary keeps W on the device.
- **Diagonal only:** `gw_lmfh` gives Σ_nn. Band features generated by
  off-diagonal Σ within (near-)degenerate manifolds — e.g. kinks at avoided
  crossings — appear only in the self-consistent band structure
  (`gwsc` + `job_band`), not in the diagonal QPE.

## Performance note: `hsfp0_gpu`

With `--gpu`, the correlation step `--job=12` runs on `hsfp0_gpu`
(CUDA-Fortran offload of the W contractions). Results are identical to the
CPU binary within double-precision summation order (≲1e-12 eV); per-rank
throughput is roughly an order of magnitude higher. The exchange steps
(`--job=3`, `--job=11`) remain on the CPU binary.
